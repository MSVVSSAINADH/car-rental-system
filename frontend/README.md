# CarRentalX frontend

The React 19 customer and administrator interface, built with Vite 7 and styled with Tailwind CSS 4. It calls the Spring Boot API through the `/api` proxy configured for local development.

For project setup, backend configuration and supported features, see the [root README](../README.md).

## Local development

From this directory, install the versions pinned by the lockfile and start Vite:

```sh
npm ci
npm run dev
```

The development server uses port `7050` and forwards `/api` requests to `http://localhost:7060`. Start the backend and MySQL database separately.

## Checks

```sh
npm run lint
npm run build
npm audit
```

There is currently no frontend test script. The production build is written to `dist/`.

## Stack

- React 19 with React Router 7. Pages are lazy-loaded per route.
- Tailwind CSS 4 through the `@tailwindcss/vite` plugin.
- `lucide-react` for icons, `sonner` for toasts, `dayjs` for dates.
- Inter and Plus Jakarta Sans, self-hosted through `@fontsource-variable`.
- `axios` for API calls, with the JWT attached by an interceptor in `src/services/api.js`.

## Structure

```text
src/
  index.css        Design tokens (colors, fonts, radii, shadows) in one @theme block
  App.jsx          Routes and the shared layout
  components/      Navbar, Footer, CarImage, forms, dialogs and other shared pieces
  content/         legal.js holds the facts used by the privacy and terms pages
  lib/             Small helpers: class names, formatting, button styles, errors, events
  pages/           One folder or file per route group (auth, customer, admin)
  services/        api, session and config
```

## Design rules

- Light theme only. Tokens live in `src/index.css`; do not add new colors or fonts elsewhere.
- Square-ish corners (8px controls, 12px cards, 6px badges). No pill-shaped buttons.
- No gradients, emoji, inline styles or global page CSS.
- Motion is limited to short hover and focus transitions, and is disabled under `prefers-reduced-motion`.
- Every number on screen comes from the API, and a section is hidden when its data is missing.
- Every data fetch has a loading state, an empty state and an error state with a retry action.
- Forms use labelled inputs with inline errors. Toasts replace `alert()`, and dialogs replace `window.confirm()`.

## Before a release

Each command should print nothing, except the first line of the `REPLACE_ME` check until `legal.js` is complete:

```sh
grep -rn "REPLACE_ME" src
grep -rn "style={{" src
grep -rnE "alert\(|window\.confirm" src
grep -rniE "made with|built with|generated by" src index.html public
```
